# 制作流程

本流程参考 **Git源宝** 的[公开视频教程](https://www.bilibili.com/video/BV1ALnw6YEM7/)及配套资料，在 AI 辅助下重新组织并补充工程核验要求。完整来源与使用范围见 [../NOTICE.md](../NOTICE.md)；引用教程方法不等于取得其原始材料的再分发许可。

## 1. 把方向变成问题

写出一条清晰的目标句：让谁，在什么场景里，理解什么。将难以验证的宏大主题缩成能在目标时长内解释的一个问题。重要数字、时间、机制和因果关系用可信来源核查，记录结论支持范围。

## 2. 把讲稿变成变化

分镜表至少包含：

| 字段 | 要求 |
| --- | --- |
| 场景 ID | 稳定且唯一，方便局部修改 |
| 起始帧／时长 | 整数，整片只使用一套 fps 和总时长 |
| 知识点 | 本段要理解的一件事 |
| 初始状态 | 对象、数量、位置与关系 |
| 变化过程 | 排序、分流、连线、反馈、合并、对照或其他可观察过程 |
| 结束状态 | 演示后关系发生了什么变化 |
| 字幕／旁白 | 与变化对应，标记重点和阅读时间 |
| 来源 | 支持事实的文献或页面 |

按“问题 → 现象 → 演示 → 应用或反例 → 回答问题”组织叙事，章节数服从内容。使用贯穿对象，如一条数据、一颗粒子或一次请求，将相邻场景连接起来。

若字幕只是叙述定义，画面只是标题和图标轮流出现，先重写变化过程，再改代码。需要比较时保证比较条件一致；示意数值应标注为示意，不能伪装为实测结果。

## 3. 让风格支持理解

确定背景、语义颜色、图形语言、字体层级、线宽和节奏。颜色可以区分不同对象或状态，不要在相邻镜头中任意更换含义。技术路线从表达需求出发，不为追求三维或特效增加无关成本。

先完成代表性场景的内部预览，再推广到全片。参考图用于说明视觉目标，不代表有权复用其中的商标、照片、音乐或其他素材。

## 4. 实现同一份时间轴

将文案、字幕和场景时间维护在同一数据源中。组件处理对象如何绘制和变化，主题配置处理配色、字体与间距。使用前闭后开的帧区间：场景起于 `from`，在 `from + durationInFrames` 之前结束。

检查类型、资源路径、中文字体、异步素材和任意帧渲染的确定性。场景转场需要解释连续性，字幕同一位置的交叉淡化不能形成叠字。

## 5. 验收实际成片

检查首尾、关键变化、每个切点前后帧、字幕阅读时间、文字边界、事实来源和音画同步。编码后核对宽高、帧率、总帧数与声音，再交付 MP4。工程、依赖锁文件、分镜与来源一并保留。

常见修复：中文方框查字体覆盖与加载；越界查真实字框和布局；字幕过快重新分配时间；PPT 感过重重新设计演示过程。

## 输入与输出示例

用户可说：

> 用 $vibe-science-video，做一条讲“推荐算法为什么越刷越懂你”的科普动画。面向普通用户，90 秒，竖屏，极简几何风，需要中文配音。

建议交付：`final.mp4`、可编辑工程、场景配置、字幕及事实来源。具体文件名服从用户项目的规范。
